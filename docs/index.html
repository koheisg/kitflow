GitFlow-style CLI for Go users and AI agents

kitflow

GitFlowの定番操作を、小さなGo製CLIで安全に実行するためのツールです。feature / release / hotfix の作成、完了、公開、追跡をシンプルなコマンドで扱えます。

GitHubを見る ユースケースを見る

インストール

go install github.com/koheisg/kitflow@latest

ソースからビルドする場合:

git clone https://github.com/koheisg/kitflow.git
cd kitflow
go build -o kitflow .

最短の使い方

kitflow init
kitflow feature start login
# edit, test, commit
kitflow feature finish login
kitflow release start 1.0.0
# final checks
kitflow release finish 1.0.0

変更系コマンドは作業ツリーがcleanであることを要求します。意図しない変更を巻き込まないためです。

コマンド一覧

目的コマンド結果
初期化kitflow initローカルGit configを保存し、可能ならdevelopを作成
feature開始kitflow feature start <name> [<base>]developまたは指定baseからfeature/<name>を作成
feature完了kitflow feature finish [name]developへno-ff mergeし、featureブランチを削除
release開始kitflow release start <version> [<base>]developまたは指定baseからrelease/<version>を作成
release完了kitflow release finish <version>mainとdevelopへmergeし、注釈付きtagを作成
hotfix開始kitflow hotfix start <version> [<base>]mainまたは指定baseからhotfix/<version>を作成
hotfix完了kitflow hotfix finish <version>mainとdevelopへmergeし、注釈付きtagを作成
公開kitflow feature publish [name]branchをremoteへpushし、upstreamを設定
追跡kitflow feature track <name>remote branchをtrackingするlocal branchを作成
確認kitflow statusmain/develop/prefix/current branchを表示

実際の利用ユースケース

1. 新機能を安全に開発する

ログイン、検索、通知など、通常の機能追加をdevelopから分離します。

kitflow feature start login
# implement login
# run tests
git add .
git commit -m "Add login feature"
kitflow feature finish login

feature/login → develop

2. Pull Request用にfeatureを公開する

レビュー前にremoteへpushし、upstream trackingも同時に設定します。

kitflow feature start search
# commit changes
kitflow feature publish search

GitHub上でfeature/searchからPRを作成できます。

3. 他人が作ったfeatureを引き継ぐ

remote branchをローカルにtracking branchとして作成します。

git fetch origin
kitflow feature track payment

ペア開発や担当交代で便利です。

4. リリース準備ブランチを切る

リリース前のバージョン調整、CHANGELOG更新、最終QAをrelease/で行います。

kitflow release start 1.2.0
# update version, changelog, docs
git commit -m "Prepare 1.2.0 release"
kitflow release finish 1.2.0

release/1.2.0 → main + develop + tag 1.2.0

5. 本番障害をhotfixで即修正する

developの未リリース変更を含めず、mainから緊急修正します。

kitflow hotfix start 1.2.1
# fix production bug
git commit -m "Fix session timeout"
kitflow hotfix finish 1.2.1

hotfix/1.2.1 → main + develop + tag 1.2.1

6. 過去の安定版からパッチを作る

保守ブランチなど、標準base以外から開始したい場合は第2引数でbaseを指定します。

git checkout -b support/1.1 1.1.5
kitflow hotfix start 1.1.6 support/1.1

複数バージョンを保守するライブラリやCLIで使えます。

7. release branchをチームに共有する

QA担当やドキュメント担当が同じrelease branchへ参加できます。

kitflow release start 2.0.0
kitflow release publish 2.0.0

別メンバーはkitflow release track 2.0.0で参加できます。

8. 作業前に何が残っているか確認する

長期ブランチが増えたときに種類ごとに棚卸しします。

kitflow feature list
kitflow release list
kitflow hotfix list
kitflow status

リリース前のブランチ整理に便利です。

9. AIエージェントに安全にGitFlow操作させる

このリポジトリにはAI coding agent向けskillも含まれています。

skills/kitflow/SKILL.md

エージェントへ「kitflowでfeature開始して」などと依頼した時の手順・安全確認を明文化できます。

実務レシピ

Solo開発: mainは常にリリース済みに保つ

kitflow init
kitflow feature start cli-help
# implement
git commit -am "Improve CLI help"
kitflow feature finish cli-help
kitflow release start 0.2.0
kitflow release finish 0.2.0
git push origin main develop --tags

チーム開発: PRレビューを挟む

kitflow feature start oauth
# commit changes
kitflow feature publish oauth
# open PR: feature/oauth -> develop
# after review and merge policy approval
kitflow feature finish oauth

リリース候補をQA環境へデプロイする

kitflow release start 3.4.0
kitflow release publish 3.4.0
# CI deploys release/3.4.0 to QA
# after QA passes
kitflow release finish 3.4.0
git push origin main develop --tags

緊急バグ修正をdevelopへ戻し忘れない

kitflow hotfix start 3.4.1
# fix and test
git commit -am "Fix billing webhook retry"
kitflow hotfix finish 3.4.1
git push origin main develop --tags

hotfix finishはmainだけでなくdevelopにもmergeするため、修正の戻し忘れを防ぎます。

設定

kitflow initは以下のローカルGit configを使用します。

git config --local kitflow.branch.main main
git config --local kitflow.branch.develop develop
git config --local kitflow.prefix.feature feature/
git config --local kitflow.prefix.release release/
git config --local kitflow.prefix.hotfix hotfix/

remote名を変えたい場合:

git config --local kitflow.remote upstream

安全に使うためのポイント

  • 作業ツリーがdirtyな状態では、branch作成・finishなどの変更系コマンドは止まります。
  • --dry-runで実行予定のGitコマンドを確認できます。
  • --verboseでデバッグ用にGitコマンドを表示できます。
  • release / hotfix finishはannotated tagを作成します。既存tag名とは衝突できません。
  • merge conflictが起きた場合はGitの通常手順で解消してください。
kitflow --dry-run release finish 1.2.0
kitflow --verbose hotfix start 1.2.1
